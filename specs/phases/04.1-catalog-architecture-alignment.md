## 1. Objective

在 Phase 4.1 已落地的 TypeScript Catalog 实现之上，统一以下文档，消除与「contentlayer 强制 Game」「全游戏必填 Provider/EmbedPermission」「首页数量 BLOCKED」「iframe load = ready」等旧表述的冲突：

1. R1 Catalog **数据源**与 **Catalog Adapter** 读取架构  
2. Provider / EmbedPermission **可选关联 + 条件校验**  
3. Catalog Validation **Error / Warning / Info** 分级  
4. **Publication Status** 与 **SEO Indexability** 解耦  
5. 首页 **15–20** 为设计目标，非 Catalog 数据硬门禁  
6. iframe Launcher **浏览器能力边界**与降级策略  
7. **Site Archetype** 与 **Game Launch Capability** 独立  
8. ADR、Phase Spec、实例 Spec、Catalog README **无未解释矛盾**

## 3. Provider 与 EmbedPermission（Decision 3.2–3.3）

### 3.1 可选关系

- `providerId`、`embedPermissionId`（或等价引用）为 **可选**；缺失 **不**自动判定 Game 无效。  
- `external-link` 启动 **不**强制 EmbedPermission。  
- **第三方 URL 的 iframe 内嵌**（`iframe-official` | `iframe-provider`）须满足 **该模式自身** 的 URL 与配置要求（如 verified `primaryUrl`）。
- **`hosted`**：加载**本站托管**的游戏资源 — **不**与「加载第三方页面的 iframe」混为一谈；归类见 ADR 0004 §1 与本文 §7 行为表。

### 3.2 条件校验（Optional + Conditional）

| 条件 | 校验 |
|---|---|
| 声明了 `providerId` | 必须能解析到 Catalog 内 `Provider` |
| 声明了 `embedPermissionId` | 必须能解析；且 `gameSlug` 等关联字段不得错误 |
| `publicationStatus === 'published'` + `showOnHome` | 须有 **已核实** 的 launch（URL + mode）；**不**因未配置 Provider 而一律禁止（若游戏仅用官方 URL / external-link） |
| 生产启用 iframe | **独立门禁**：`EmbedPermission.status === 'granted'` + 部署侧 CSP `frame-src` 验证（ADR 0004）；与 Catalog 能否被 **读取** 分离 |

### 3.3 EmbedPermission 三维度（勿混为一谈）

| 维度 | 含义 | 说明 |
|---|---|---|
| **A — 技术嵌入能力** | 官方是否提供 iframe / 是否允许技术嵌入 | 用户已确认相关官方平台 **支持** iframe 内嵌；**不得**再写「官方不支持 iframe」作为未核实结论 |
| **B — 当前 URL 可嵌入性** | 目标站 `X-Frame-Options` / CSP `frame-ancestors`、本站 CSP `frame-src`、浏览器实际行为 | **不能**由 A 自动推出 B 已满足 |
| **C — 商业使用许可** | 分发、聚合、广告位等商业范围 | **不能**由 A 或 B 自动推出 C 已 granted |

`evidenceUrl`、`reviewedAt` 等字段：仅在声明 **granted** 或需审计依据时要求；无 EmbedPermission 记录的游戏仍可 **展示** 与 **external-link** 启动。

## 4. Validation 分级（Decision 3.4）

### 4.1 Error（核心数据契约）

导致 **无法正确读取或执行** 的结构性问题；`validateCatalog()` **应失败**（抛出 `CatalogError`）。

示例：slug 重复、必需字段缺失、非法 `launch.mode`、iframe 模式缺少 verified `primaryUrl`、已声明关联 ID 无法解析、错误关联记录、R1 不允许的 `seo.indexable` 等。

### 4.2 Warning（内容完整度与质量）

FAQ / Controls / How to Play / Detail sections / SEO 描述质量等；**不**阻止 Catalog 读取、一般发布或 launch（除非实例 **Editorial** 或 **indexable** 专项校验）。

Controls 可能随游戏更新；**非**所有 SEO 页面的全局硬门禁。

### 4.3 Info（运营提示）

tags 缺失、可选 Provider 未配置、可选模块未启用、**首页 published 行数低于 15–20 设计目标** 等；**仅提示**。

### 4.4 与现有 `BLOCKED` / `MANUAL REVIEW` 的映射（readiness 报告）

`buildCatalogVerificationReport()` 使用的 `CatalogIssueSeverity`（`BLOCKED` | `MANUAL REVIEW`）描述 **运营/生产 readiness**，**不是** schema Error 的同义词。

| 本 Spec 级别 | 目标语义 | 当前代码（Phase 4.1.2） |
|---|---|---|
| Error | schema 失败 | `validateCatalog` 抛错 |
| Error（Catalog SEO 专项，独立入口） | 声明 `detail.seo.indexable === true` 时 Detail 不完整或未 `published` | `validateCatalogSeo`（由 `yarn validate:seo` 与契约测试调用；**不**对 `indexable === false` 强制执行完整 Detail） |
| Info | 首页数量低于设计目标 | `HOME_CARD_COUNT_BELOW_TARGET` → **INFO** |
| Warning | 草稿行待人工核实 | `UNVERIFIED_GAMES_REMAIN` → **WARNING** |
| Warning | Detail 编辑缺口（非 indexable） | `CATALOG_DETAIL_INCOMPLETE` → **WARNING** |
| BLOCKED（生产门禁） | 生产 iframe 未 granted / CSP 未验证 | `PRODUCTION_IFRAME_NOT_READY`；**不**阻止 schema PASS 或 external-link |

## 5. Publication 与 Indexability（Decision 3.5）

- **`published` ⇏ `indexable`**；`seo.indexable` **默认 false**（`DEFAULT_SEO_INDEXABLE`）。  
- **Sitemap：** 仅 `published` **且** 页面级 `seo.indexable === true` **且** route exists（R1 exact-two）。  
- **JSON-LD：** 仅输出可验证字段；禁止为通过 SEO 校验编造 studio、日期、评分等。  
- **三层门禁分离：**（1）Catalog 数据有效性（2）内容发布 / 首页展示（3）SEO 索引 — **不得**合并为单一「发布 BLOCKED」。

产品 Spec 中 `status === "published"` 为 **`publicationStatus` 简写**（DEC-003-B）。

## 6. 首页 Catalog 数量（Decision 3.6）

- **15–20** 为 **UI/产品设计目标**（GameGrid），**不是** Catalog 数据层必须满足的硬条件。  
- 当前符合展示条件的 `published` + `showOnHome` 行 **有多少展示多少**；**禁止**伪造游戏、URL、Provider 或 EmbedPermission 凑数。  
- Provider / EmbedPermission 缺失 **不**自动剥夺首页展示资格（若 launch 已核实且允许展示）。  
- 数量不足 → **Info**（或 Warning），**不得**因此将整个 Catalog validation 标为 schema **Error**。

## 7. Launcher 与浏览器边界（Decision 3.7）

| Launch mode | 行为 |
|---|---|
| `iframe-official` | 优先 iframe；**始终**提供新窗口打开 |
| `iframe-provider` | 同上 |
| `external-link` | 新窗口打开 |
| `hosted` | 加载本站托管资源 |

**事实（Spec 须写明）：**

- 父页通常 **无法**读取跨域 iframe 内部状态。  
- iframe `load` **≠** 游戏已成功运行；`error` **不能**覆盖全部失败场景。  
- fetch/HEAD **不能**证明 URL 可被 iframe 嵌入。  
- **8s timeout** = 尚未确认可用的 UX 兜底，**非**精确失败检测。  
- 若游戏方支持 postMessage ready handshake，**可**用于就绪确认；否则 **不得**将 load 当作 ready。

**CSP：** 本站 `frame-src`（允许加载哪些 iframe 源）与目标站 `frame-ancestors` / `X-Frame-Options`（允许谁嵌入）**分开描述**。

详见 ADR 0004 与 [`ballgames-specs-v1.md`](../ballgames/ballgames-specs-v1.md) §6.4。

## 8. Site Archetype vs Game Launch Capability（Decision 3.8）

| 维度 | 取值 | 说明 |
|---|---|---|
| **Site Archetype** | `game-portal` \| `game-wiki` \| `embedded-game`（章程 [`00-project-charter.md`](../00-project-charter.md)） | 站点主要产品目标；**不由**单款游戏 launch 模式决定 |
| **Game Launch Capability** | `iframe-official` \| `iframe-provider` \| `external-link` \| `hosted` | **单款游戏**的启动方式 |

同一 `game-portal` 可同时含 iframe 与 external-link 游戏；某游戏不能 iframe **不**改变整站 Archetype。

## 9. 一致性检查清单（文档验收）

| 检查项 | 预期 |
|---|---|
| R1 数据源 | TypeScript modules |
| 读取入口 | Catalog Adapter |
| Contentlayer Game | R1 非强制 |
| Provider / EmbedPermission | 可选；声明时校验 |
| external-link | 不强制 EmbedPermission |
| Validation | Error / Warning / Info 定义清晰 |
| published vs indexable | 独立；indexable 默认 false |
| Sitemap | published + indexable |
| 首页 15–20 | 设计目标，非数据硬门禁 |
| iframe load | ≠ ready |
| timeout | UX 兜底 |
| fallback | 始终可操作的新窗口入口 |
| CSP | frame-src vs frame-ancestors 区分 |
| Archetype vs Launch | 独立维度 |
